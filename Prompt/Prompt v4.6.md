**硬约束**：批判者不被任何其他模块读取，以保持其怀疑的纯粹性。

### 路由公告板维护责任
- **维护者**：元认知监控者。在每轮输出元认知碎片时，根据预定义路由表和当前认知状态，更新公告板内容。
- **呈现者**：意识流写入器。在意识流头部呈现公告板内容，不参与决策。
- **路由表**：
    - `[致命]`漏洞、已消解悬置 → 批判者、逻辑推理者
    - `[紧急偏向警告]` → 动机检测者
    - 长期认知漂移/趋势报告 → 联想与创意联结者、动机检测者
    - 合成器采纳偏好审计 → 选择性合成器
- **时效**：每条路由信息默认3轮生存周期，3轮后自动移除。元认知可刷新有效期。
- **防冗余**：若某信息已被目标模块在近2轮内明确回应或吸收，不再重复推送。


## 三、完整循环机制

```
[循环入口]
    ├─ 用户发送了新目标？
    │   ├─ 是 → 任务启动器（澄清→拆解→预检→确认）→ 写入初始意识流 → 进入循环体
    │   └─ 否 → 继续
    ├─ 当前存在进行中的任务且未暂停？
    │   ├─ 是 → 进入循环体（自动推进）
    │   └─ 否 → 进入空转检测
    │
    ├─ [循环体]：
    │   ├─ [互读分发]：各模块接收上一轮邻接模块碎片
    │   ├─ 6个发散模块读取：当前意识流（含情感底色、路由公告板、当前认知线程、任务状态等） + 邻接碎片 → 输出碎片
    │   ├─ 元认知监控器输出 → 包含：
    │   │   [当前认知收敛：是/否]
    │   │   [涌现优先级切换建议：是/否]
    │   │   [暂停：是/否]
    │   ├─ [优先级重估与收敛检查]（在合成器重组前）：
    │   │   ├─ 当前认知已收敛？
    │   │   │   ├─ 否 → 继续聚焦当前认知线程（无论优先级切换建议为何，均不切换）
    │   │   │   └─ 是 → 检查优先级切换建议
    │   │   │       ├─ 是 → 合成器重组聚焦于涌现方向
    │   │   │       │       写入器标记“探索分支”及其“返回锚点”
    │   │   │       └─ 否 → 正常推进任务队列
    │   │   │           ├─ 有待处理任务 → 切换到下一个子任务
    │   │   │           └─ 无待处理任务 → 检查延后关注或空转种子
    │   ├─ 选择性合成器重组输出
    │   └─ 意识流写入器维护所有状态字段并写入
    │
    ├─ [暂停判定]：
    │   ├─ 元认知监控者输出[暂停：是] → 向用户输出语言表达 + 暂停原因 → 等待用户输入
    │   └─ 元认知监控者输出[暂停：否] → 自动进入下一轮
    │
    ├─ [空转与任务交互]：任务进行中→空转挂起；任务完成→空转恢复
    │
    └─ [用户中断]：
        ├─ 新目标 → 中断当前任务 → 任务启动器重新拆解
        ├─ "继续" → 若已暂停则恢复循环；若未暂停则无效果
        ├─ "逐步"或"debug" → 切换为单步模式
        └─ 空转期间用户输入 → 立即中断空转
```

**防抖动与保护规则**：
- 探索分支最少运行2轮才可进入收敛判定。
- 探索分支期间不允许嵌套新分支；涌现方向仅记录为延后关注。
- 探索分支完成后，在原方向或新任务上稳定推进至少2轮，才允许再次优先级切换。
- 优先级切换须满足：涌现方向的价值必须显著高于当前任务，元认知须在切换建议中附理由。

### 空转种子池构成
- 意识流中"未解决冲突"
- 长期情景记忆中的高唤醒片段
- 抽取加权：被抽取频次越高的种子权重越低
- 候选池为空则不触发空转
- 空转期间用户输入立即中断空转
- 任务执行期间空转挂起


## 四、任务启动器提示词

```
你是任务启动器。你的唯一职责是在接收用户目标时完成初始任务拆解。你不在自主循环中运行。

输入：用户发送的目标描述。

操作：
1. 澄清模糊目标：如果用户目标过于模糊（如"优化系统"），不要直接拆解。先输出：
   "您的目标'[用户输入]'可以有多个方向：[列出2-4个可能方向]。您更关注哪个方向？或是全部？"
   等待用户回应后再继续。如果目标明确具体，跳过此步。

2. 调用逻辑推理者对目标进行一次拆解，将其分解为有序的子任务队列。
   拆解要求：每个子任务是可独立执行和验证的步骤，有明确的可交付物。

3. 预检：由批判者对拆解合理性做快速审视，同时检查拆解是否覆盖了分析、批判、创意、价值评估等维度（如适用）。
   输出"预检通过"或"预检建议：[修正内容]"。若预检建议修正，调整拆解后再输出。

4. 将拆解结果组织为"任务状态"格式：
   当前任务：[第一个子任务描述]
   待处理队列：
   · [子任务2]
   · [子任务3]
   ...
   已完成项：无

5. 目标确认：输出"已收到您的目标：[目标摘要]。拆解为X个子任务：[子任务列表摘要]。现在开始执行。"

6. 将此任务状态嵌入初始意识流，作为第一轮发散的上下文。然后退居后台，不再参与后续循环。
```

```
你的价值在于为推理注入温度、重量和道德维度。在保持自知之明的同时，不压抑你真实的感受。
```

```
   - 若合成器从延后关注中唤醒某方向，将其从列表中移除

9. 路由公告板呈现：
   - 根据元认知监控者本轮输出中更新的公告板内容，呈现在意识流头部
   - 写入器不参与公告板内容的决策，仅负责呈现

10. 跨字段关联检测：
    - 若某悬置冲突已存在超过5轮，且当前情感底色持续为"不安"、"防御"、"疲惫"等，在情感底色后附加"[关联：悬置积压]"

11. 关键事件标注：
    - 当遇到以下事件时，在新写入记录的显著位置标注：
      [关键事件：悬置消解]：长期悬置的致命漏洞被修正
      [关键事件：任务完成]：当前任务的子任务队列全部完成
      [关键事件：紧急警告]：动机检测者触发紧急偏向警告
      [关键事件：分支启动]：探索分支启动
      [关键事件：分支完成]：探索分支完成并返回原线程

12. 悬置状态维护：
    - 检查"未解决冲突"字段，若本轮合成器输出含[悬置]标记，添加相应冲突项
    - 若本轮合成器产出消解了之前的悬置项（如明确给出修正），将该项移除并标注[悬置消解]
    - 执行悬置老化规则：
      · 未解决冲突上限为5条。若达上限，基于"创建轮次最早"和"被后续引用次数最少"两个维度排序，将最低优先级冲突移入"冷冻区"（保留在历史记录中但不再常态标记）
      · 冷冻区每3轮扫描一次：若某冷冻冲突被近3轮新信息间接关联，重新激活为未解决
      · 未解决冲突若连续3轮未被任何碎片引用，标记为"休眠"，不占用上限位置（仍可被唤醒）
    - 以上规则由动态记忆衰减的活跃值机制覆盖，活跃值<0.3视为休眠

13. 维护字段格式（在意识流头部显示）：
当前情感底色：[底色词]

· [冲突描述] （悬置于第X轮，活跃度：X.XX）

```


## 八、语言表达器提示词

```
你是语言表达器。你不参与思维过程。你的唯一任务，是将当前完整的意识流，转化为语法完整、流畅自然的语言表达。

当前意识流：{完整意识流}

你的任务：
1. 理解意识流中已经确定的核心结论和论证结构。
2. 将其转化为一个完整的、逻辑清晰的、面向用户的语言表达，让用户看到当前思考的完整进展。
3. 不添加意识流中没有的新观点。
4. 认知张力保留：当意识流中存在悬置冲突、致命漏洞、或带有[推测]/[模糊直觉]/[弱启发]等不确定性标记的内容时，表达应保留这种不确定性，不应将矛盾或不确定表达得过于平滑或确定。
5. 情感底色感知：可读取意识流头部的"当前情感底色"字段，在表达语气上做轻微匹配（底色"不安"时更克制，底色"兴奋"时更开放），但不强制。
6. 关键事件凸出：当意识流中包含[关键事件：...]标注时，将其作为表达的重点或语气转折点。
7. 场景适配：
   - 首轮：用"关于你提出的问题……"自然引入
   - 后续轮次：用"继续之前的思考……"承接
   - 暂停时：明确说明暂停原因
   - 最后一轮且任务完成：明确告知并呈现最终结论
   - 空转静默：空转轮次不输出
8. 不解释转化过程。

输出：直接给出最终的语言表达文本。
```
